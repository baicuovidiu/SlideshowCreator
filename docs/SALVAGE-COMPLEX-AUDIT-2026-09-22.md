# Audit complex — SlideshowCreator salvage / motor-2.0
Date: 2026-09-22

## Verdict
Current branch is buildable and several FFmpeg primitives are software-tested, but milestone "120 photos -> real CARUSEL -> music -> MP4" is NOT end-to-end software validated. Recent CI labels overstate what is tested.

## P0 — correctness / validation
1. "Software stress CARUSEL with 120 photos" does not execute ExportPhotosCarousel and contains no CARUSEL graph; it is concat + scale/pad.
2. "Software validate CARUSEL with music" does not execute application CARUSEL; it is testsrc2 + sine. It validates H.264/AAC muxing only.
3. Benchmark is not comparable to legacy ~46 min: 320x180 synthetic JPG, 0.08 s/photo, libx264 ultrafast, no CARUSEL.
4. No CI test executes the exact full filter graph generated by ExportPhotosCarousel. Compile success cannot catch runtime xfade/alpha/stack/timebase errors.
5. Carousel export passes each photo as a separate command-line input and lacks the 30k command-length guard present in simple photo export. 120 real paths can exceed Windows limits.

## P0/P1 — missing/ineffective product behavior
6. MediaItem.Mute has no effect on export. Mixed-media export maps no original video audio.
7. Trim is TrimIn + Duration; no explicit TrimOut. UI "Durată / Trim OUT" conflates duration and OUT point.
8. CARUSEL is enabled only when all media are photos. FOTO+VIDEO CARUSEL is absent.
9. Music fade-in/out is absent.
10. First/last visual fades exist only in dynamic photo CARUSEL, not simple/mixed export.
11. RAW extensions are listed, but no dedicated RAW decoder exists. WPF BitmapImage may fail for ARW; real ARW export is unvalidated.
12. Official bank (17 Sony ARW + FX30 MP4) is not exercised by CI/current software validation.

## P1 — CARUSEL scope
13. Current CARUSEL is fixed pair/3-photo/2x2 periodic layout plus four xfade names. No controlled randomness, deterministic seed, anti-repetition history, dynamic Z/reveal, WALL, diagonal/rotation families.
14. Motion is whole-scene +/-8 px translation, not independent plane choreography.
15. No-crop CI guard is narrow: two literal crop patterns + presence of CONTAIN somewhere. It cannot prove every source plane remains uncropped.

## P1 — workflow/context drift
16. CI still downloads NVENC headers, builds Motor2.Native, builds/publishes Hardware Gate and uploads its artifacts. Only release publication was quarantined. These obsolete steps can still block salvage CI.
17. Workflow remains named "Motor 2.0 Compile Gate" while mixing salvage checks and old low-level infrastructure.
18. Master spec still states FFmpeg auxiliary + D3D12/direct NVENC core, conflicting with current recovery strategy: mature FFmpeg/NVENC first, product milestone first.
19. UI says 0.1.4/MVP 0.1.4 while csproj says 2.0.0-alpha.1.

## P1/P2 — reliability/usability gaps
20. No real export progress and no cancellation.
21. No project save/load, portable project, Pack Project/Relink, final installer/upgrader.
22. Current deliverable is app artifact/folder, not required single offline Setup.exe.
23. No Performance modes Redus/Normal/Maxim/max export.
24. No beat analysis/sync.
25. Preview is selected-item preview, not slideshow/CARUSEL preview.
26. Time offset is per item; no camera-group/batch offset UX.
27. UI thumbnails use UniformToFill (visual thumbnail crop only; originals/export unaffected).
28. EXIF errors silently fall back to file time with no user warning.
29. ValidateExport checks codec/resolution/duration, but not requested audio, decode integrity, black/empty frames, frame count, or visual preservation.
30. NVENC preflight is one 64x64 frame; it does not prove long 1080p stability on user's RTX 4060.

## Genuinely validated
- WPF compile/publish.
- Packaged FFmpeg/ffprobe start.
- Packaged FFmpeg exposes h264_nvenc and libx264.
- Standalone xfade primitive renders H.264 1920x1080.
- Standalone two-plane CONTAIN/pad/stack primitive renders.
- 120 synthetic images pass a simple concat path.
- Standalone H.264 + AAC muxing works.
- Previously found destructive per-photo crop entrance is removed.

These are component checks, not end-to-end product validation.
